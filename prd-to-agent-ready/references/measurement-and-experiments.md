# 可观测性与实验设计

重要业务流程需要检查效果是否能被观测。只有用户明确提出 A/B，或原文及已确认产品目标要求实验验证时，才创建正式实验契约。缺少这样的依据时不引入分组、分流、奖励或流程差异；实验机会只放入非强制建议。

## 可观测性

按功能目标检查以下维度是否适用：曝光人数、开启人数、关键操作人数、各阶段转化率、成功率、失败率、退出率、关键耗时、收入、奖励产出、不同用户群体的行为差异。不是每个功能都需要全部指标。

重要指标使用稳定 ID 并尽可能明确：

| 字段 | 契约内容 |
| --- | --- |
| 目标及来源 | 为什么观察此指标，对应的产品目标、流程阶段、需求与来源 |
| 定义及公式 | 事件、人数、次数或金额；比例的分子、分母及过滤条件；耗时的起止事件与单位 |
| 统计范围 | 用户资格、统计窗口、平台及版本范围、业务周期、币种等适用口径 |
| 去重 | 用户、会话、业务请求或活动实例等去重实体及时间范围 |
| 数据来源 | 对应事件、配置或业务结果；数据缺失如何影响指标解释 |
| 触发时机 | 真实曝光、进入、操作、结果确认、退出等具体时点，区分意图和结果 |
| 关联属性 | 为分群、阶段或版本归因确有需要的业务标识，不自行增加个人信息采集 |
| 校验与未决项 | 计算及事件关联的验收、口径问题、责任角色 |

不要仅罗列事件名。已有材料缺少分母、去重或触发时点时，写 TBD 和数据或产品角色的问题。由名称猜出的口径不能升级为正式定义；可以提供未选定的候选口径，说明它们回答的问题有何不同。

区分原文明示的观测要求、由已有定义可严格推导的计算口径、待确认指标和非强制建议。检查必要观测能力不意味着可以无来源地创建正式埋点、采集字段、目标阈值或发布门槛。

## 正式实验的适用判断

先记录实验需求的 Source。若需求只写“上线后看效果”，先定义或澄清观测口径；不能据此自动生成 A/B 分组。

原文明确要求实验但设计不完整时，保留实验需求并登记下列缺口。分组、统计参数及实验周期未知时不得选常见默认值。实验依赖是否阻塞功能主体、只阻塞实验部分或阻塞发布，必须按具体依赖说明，不一概判断。

## 实验契约

### 定义

记录 Experiment ID、实验目标、假设、背景、预期改善指标、关联需求和来源。若 ID 尚未分配，用本地追踪 ID 关联，并把正式 Experiment ID 标为 TBD，不虚构平台上已存在的实验。

### 分组与配置版本

明确 Control Group、Treatment Group、用户分配比例及规则、是否需要固定分组、重新安装或跨设备是否影响分组、实验版本与配置版本。多组实验按原文保留，不为了模板强制变成两组。

比例必须有来源并检查合计与实际纳入流量一致。区分配置目标比例、实际样本占比及偏差验收标准；原文只给出比例时，保留该声明并将分配方法和验收口径记为待确认，不能自行解释成随机概率、精确配额，或默认允许样本偏差。固定分组、白名单、排除规则、回流用户和已参与用户如何处理都不能自行决定。

### 变量、固定条件和观测指标

单独列出三者，不混成“实验配置”。

可检查的变量包括开启条件、弹出时机与频率、奖励内容与数量、价格、礼包顺序、UI、动画和引导方式；只选择正式需求允许变化的项。

对比各组，检查是否无意改变多个因素，导致无法区分效果来源。原文确实要求组合变化时保留并说明可解释性限制，必要时提产品决策问题，不能自行改造成另一种实验。

### 指标与判定

区分 `Primary Metric`、`Secondary Metrics` 和 `Guardrail Metrics`，并对每个指标采用上面的完整口径。不要把所有指标都归为核心指标。

根据实验目标可考虑 D0 / D1 留存、参与率、礼包项完成率、广告完成率、付费转化率、ARPDAU、人均收入和退出率；这些只是候选维度，不是默认必须采集的指标。

记录目标方向、成功标准、保护性指标的容忍范围及结论规则。未给出的阈值写 TBD，不自创“提升 5%”或统计显著性要求。

### 可靠性

检查样本污染、重复分组、跨实验干扰、平台或客户端版本差异、用户排除、实验周期和结束条件、是否需预先确定样本量及统计显著性标准。

分别记录已确认约束、数据分析需要验证的事项和业务决定。没有基线或统计设计时，不编造样本量、显著性阈值、统计方法或周期，也不把没有口径的数据当作可比较样本。

### 配置与生效

优先检查实验变量能否使用项目现有配置体系，记录谁提供、哪些字段允许变化、配置与分组版本如何对应、进行中用户受变更影响的规则。是否需要配置化应结合现有体系及产品要求确认，不强制新增远程配置平台。

分组与配置归因不明确时记录问题，不能让相同实验组悄悄对应不同业务规则。实验结束后的恢复、保留、关闭或全量行为需要正式决定，不默认自动发布获胜组。

### 结论与验收

按照预先定义的指标与规则，应能判断实验是否有效、是否达到目标、是否有负面影响、是否继续实验以及是否适合全量。判断依据缺失时保持 TBD，不事后补阈值解释结果。

将分组资格与比例、固定分组、变量生效、固定条件、版本归因、指标触发与计算、结束与恢复关联 REQ / BR / SC / AC。这里定义的是待执行的验收，不能将尚未运行的实验写成结论已验证。
